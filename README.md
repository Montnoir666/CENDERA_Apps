# CENDERA — Oil Palm WC Dashboard

*by Cendera Technologies*

A self-contained project that syncs mid-canopy FPV drone frames with their
metadata and serves a login-gated, per-estate-scoped, interactive 3-tab web
dashboard for the PhD working chapters (WC1 real; WC2 & WC4 mock
placeholders).

## What it does

1. **`scripts/setup_folders.py`** — creates the folder scaffold (`data/<estate>/`, `outputs/`).
2. **`scripts/build_wc1_assessment.py`** — for each flight folder under `data/<estate>/`,
   keeps only the metadata rows whose frame image is present in the folder
   (your manual sort), and writes one workbook to
   `outputs/WC1_agronomic_assessment_synced.xlsx` with two columns for you to
   fill in: a drop-down `agronomic_assessment_type` and free-text `remarks`.
3. **`scripts/setup_accounts.py`** — one-time bootstrap for `accounts/users.xlsx`
   (see Login below).
4. **`app/app.py`** — Flask app that reads the filled workbook and serves the
   CENDERA dashboard behind a login screen at `http://localhost:5000`, scoped
   to each user's assigned estate(s).
5. **`scripts/build_dashboard.py`** *(optional)* — legacy static exporter; writes a
   login-free `wc1_dashboard.html` snapshot at the project root, useful for a
   quick offline copy. Not needed for normal use — use `app/app.py` instead.

**Two hard rules:** the frame images must live inside `data/<estate>/` (copy
them in, so the project is portable), and estate folder names are what both
the dashboard's Estate dropdown and `accounts/users.xlsx`'s `estates` column
refer to — keep them consistent.

## Setup & run

```bash
pip install -r requirements.txt

python scripts/setup_folders.py       # once — makes data/<estate>/ + outputs/
# then copy each flight folder + its _frame_metadata.csv into data/<estate>/

python scripts/build_wc1_assessment.py   # -> outputs/WC1_...synced.xlsx
# open the workbook, fill agronomic_assessment_type (drop-down) + remarks

python scripts/setup_accounts.py      # once — makes accounts/users.xlsx

python app/app.py                     # -> http://localhost:5000
```

All commands are run from the project root regardless of OS — every script
resolves paths from its own location, not the current directory.

## Login & per-estate access

CENDERA is gated behind a login screen (real server-side sessions). Unlike
the assessment workbook, credentials live in a plain **Excel file you edit
directly**: `accounts/users.xlsx` (columns `username`, `password`, `role`,
`estates`), bootstrapped once by `scripts/setup_accounts.py`.

| username | password | role | estates |
|---|---|---|---|
| admin1 | ChangeMe-Admin1 | admin | *(ignored — sees everything)* |
| admin2 | ChangeMe-Admin2 | admin | *(ignored — sees everything)* |
| serdang2_manager | ChangeMe-Serdang-2 | user | Serdang-2 |

- `role` is a dropdown: `admin` (sees every estate, no matter what's in
  `estates`) or `user` (restricted to exactly the estate(s) listed).
- `estates` is comma-separated for a user assigned more than one estate, e.g.
  `Serdang-2, Rembau`. Names must match a `data/<estate>/` folder name.
- **To add, edit, or remove a login: just edit the spreadsheet and save.**
  The app re-reads it on every login and every page load — no restart
  needed. Deleting a row logs that user out on their next click.
- **Change the placeholder passwords** before handing accounts out — this
  file ships with obvious `ChangeMe-...` values.
- **Security tradeoff, stated plainly**: passwords in this file are
  **plaintext**, not hashed — that's the necessary cost of "edit it like a
  spreadsheet." `accounts/users.xlsx` is gitignored; treat it like any other
  secret (don't email it, don't screen-share it, restrict who can open the
  folder).
- Restriction is enforced both on the map data (a restricted user's Estate
  dropdown only ever shows their own estate(s)) and on the frame-image URLs
  (`/media/<estate>/...` 404s if that estate isn't in the requester's list).

**Keeping the live site's accounts in sync**: `accounts/users.xlsx` and the
Render deployment's `users.csv` Secret File are two separate copies (that's
intentional — passwords never go through git). After editing the local
spreadsheet, run:
```bash
python scripts/sync_accounts_to_render.py
```
This converts `users.xlsx` to CSV, pushes it to Render via their API, and
triggers a redeploy (Render doesn't hot-swap secret files into an already
running instance, so a redeploy is required for the change to actually take
effect). One-time setup: add `RENDER_API_KEY` (Render dashboard → Account
Settings → API Keys → Create API Key) and `RENDER_SERVICE_ID` (the `srv-...`
id in the service's dashboard URL) to `.env` — see `.env.example`.

Also set a real `SECRET_KEY` in `.env` (copy from `.env.example`; see its
comment for how to generate one) before this is ever reachable outside your
own machine — without it, sessions can be forged.

## Deploying to Render (so other people can reach it)

Running `python app/app.py` only serves `localhost` — nobody outside your
own machine can open it. To give other people a real URL, deploy to
[Render](https://render.com) (free web-service tier, reads the `Procfile`
automatically):

1. **Push this project to a private GitHub repo.** `data/` and `outputs/`
   are committed (not gitignored) so the deploy has real data to serve out
   of the box; `accounts/users.xlsx` stays gitignored — see step 5, it
   never goes in git.
2. **Render → New → Web Service**, connect that GitHub repo. Render detects
   the `Procfile` (`web: cd app && gunicorn --bind 0.0.0.0:$PORT app:app`)
   automatically — no build command needed beyond
   `pip install -r requirements.txt` (Render's Python default).
3. **Environment tab** → add:
   - `SECRET_KEY` — generate with
     `python -c "import secrets; print(secrets.token_hex(32))"`
   - `GOOGLE_MAPS_API_KEY` — your key (billing must be enabled on its project)
4. **Secret Files tab** → add one named `users.csv`
   (mount path `/etc/secrets/users.csv`), and paste your accounts as CSV —
   same four columns as `accounts/users.xlsx`:
   ```
   username,password,role,estates
   admin1,ChangeMe-Admin1,admin,
   admin2,ChangeMe-Admin2,admin,
   serdang2_manager,ChangeMe-Serdang-2,user,Serdang-2
   ```
   `app/auth.py` prefers this secret file over the local `accounts/users.xlsx`
   automatically whenever it's present — that's the whole mechanism, nothing
   else to configure. Locally (no secret file present) nothing changes: you
   still just edit `accounts/users.xlsx` in Excel.
5. **Deploy.** Render gives you a `https://<name>.onrender.com` URL — that's
   what other people open and log into. To update accounts later, edit the
   Secret File's content in Render's dashboard (no redeploy of code needed);
   to update data, push new commits (`data/`, `outputs/`) to the repo.

## Key behaviours

- **Estate** = the `data/<estate>/` folder name (rename/add freely; the scripts
  and dashboard dropdowns adapt automatically) — also what `accounts/users.xlsx`
  uses to scope non-admin logins.
- **Assessment month** = auto-derived from the flight-folder timestamp
  (`DJI_YYYYMMDD…` → `YYYY-MM`). No manual month sorting needed.
- **Merge-safe re-runs**: re-running `build_wc1_assessment.py` after adding new
  frames preserves assessments/remarks you already typed (keyed on
  flight folder + frame filename) and only adds new blank rows.
- **Frame-image matching** de-duplicates case-insensitively (Windows glob quirk)
  and matches on filename stem.
- **Declutter**: WC1 GPS is near-static (position-holding), so overlapping
  markers are fanned onto a ~2 m circle for clickability — the popup still shows
  the TRUE lat/lng, not the display-offset position.

## Dashboard tabs

- **WC1 Assessment (REAL):** markers coloured by 4 assessment types
  (Nutrient Deficiency, Pest & Disease, Frond Pruning/Canopy Condition,
  Ground Condition), Estate + Month dropdowns, per-type toggles, and a
  coordinate + frame IMAGE popup.
- **Bunch Development (MOCK):** placeholder for WC2 — points coloured by
  predicted days-to-ripe. Banner-flagged as mock.
- **Yield (MOCK):** placeholder for WC4 — per-palm predicted yield (kg), graduated
  circles. Banner-flagged as mock.

## Swapping mock → real data (future)

In `core/dashboard_data.py`, replace the `mock_bunch()` and `mock_yield()`
functions so they read real WC2 / WC4 outputs (same dict shape: `lat`, `lng`,
plus `stage`+`days` for bunch, `palm`+`yield_kg` for yield). Both `app/app.py`
and `scripts/build_dashboard.py` pick up the change automatically; the tabs,
colours, and layout stay as-is.

## Config notes

- The Google Maps API key is read from the `GOOGLE_MAPS_API_KEY` env var (see
  `.env.example`), falling back to a built-in default. Update it in `.env` if
  it ever changes.
- If the frame-filename column isn't auto-detected in a metadata file, set
  `FRAME_COL_OVERRIDE` at the top of `scripts/build_wc1_assessment.py`.
- Frame images are served through `/media/...` (login- and estate-protected)
  rather than as static files, so they aren't reachable by anyone without a
  session that's allowed to see that estate.
